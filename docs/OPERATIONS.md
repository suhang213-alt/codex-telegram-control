# Работа с ботом и панелью

В выпуске 0.2 основной сценарий — существующие локальные чаты Codex Desktop на Mac. Отдельный CLI-режим сохранён и имеет другие команды, профиль и права. Один бот и один каталог данных обслуживает один процесс моста.

## Выберите свой режим

| | Mac Desktop | Отдельное CLI-ядро |
|---|---|---|
| Команда | `codex-telegram-desktop` | `codex-telegram` |
| Чаты | Существующие чаты Desktop в выбранной рабочей папке | Чаты, созданные этим экземпляром моста |
| Движок | Встроенный движок, запущенный Desktop | Собственный дочерний app-server |
| Вход | Уже выполнен в Desktop | `codex-telegram login` в изолированном профиле |
| Права | Действующие настройки Desktop | `read-only`, `on-request`; возможен явный `workspace-write` |
| Проверка | `codex-telegram-desktop doctor` | `codex-telegram doctor --protocol` |
| Установка | [Mac + Samsung](INSTALL_MACOS.md) | [Windows/Linux](INSTALL_WINDOWS_LINUX.md) |

Windows Desktop-адаптер обслуживается по [своей инструкции](../adapters/windows_desktop/README.md). Команды Mac-адаптера к нему не относятся.

## Запуск Mac Desktop и моста

После первоначальной настройки дождитесь окончания задач и завершите Desktop через Quit / Cmd+Q. Из корня пакета:

```sh
.venv/bin/codex-telegram-desktop launch
.venv/bin/codex-telegram-desktop doctor
.venv/bin/codex-telegram-desktop run
```

Если Desktop уже запущен этим launcher и `doctor` подтверждает готовое соединение, для повторного запуска моста достаточно `run`. `launch` не подключает обёртку к уже работающему процессу и не закрывает его принудительно.

Мост работает в текущем терминале. Ctrl+C останавливает мост, оставляя Desktop и его задачи работающими. Чтобы остановить конкретную задачу, используйте `/stop` или Desktop. Туннель работает в отдельном окне. Автозапуск этой установкой не создаётся.

Mac должен оставаться включённым, бодрствующим и подключённым к сети. После сна или разрыва проверьте исходный чат на Mac. При необходимости остановите мост, выполните `doctor` и `run`; после штатного перезапуска Desktop потребуется `launch`. При неоднозначном наборе движков удалённые действия блокируются. Подробности и откат — [MACOS_DESKTOP](MACOS_DESKTOP.md).

## Команды личного чата

| Команда | Mac Desktop | CLI-ядро |
|---|---|---|
| `/start`, `/help` | Справка выбранного режима | Справка выбранного режима |
| `/chats` | Существующие разрешённые локальные чаты | Чаты этого экземпляра |
| `/use номер` | Явно выбрать чат из списка | Выбрать чат из списка |
| `/new название` | Создавайте чат непосредственно в Desktop | Создать и выбрать собственный чат |
| Обычный текст | Продолжить выбранный исходный чат | Отправить задание в выбранный чат |
| `/panel` | Открыть Mini App | Открыть Mini App |
| `/status` | Состояние выбранного чата и соединения | Состояние выбранного чата и соединения |
| `/stop` | Запросить остановку выбранной активной задачи | Запросить остановку выбранной активной задачи |
| `/files`, `/get имя_файла` | Подготовленные файлы рабочей области | Подготовленные файлы рабочей области |

Перед отправкой проверьте выбранный чат; в настройках панели показан его ID. В Desktop-режиме чат не выбирается автоматически при первом запуске. Голосовые сообщения эти два режима не расшифровывают. Для файлов используйте загрузку в панели.

## История, состояние и решения

Панель показывает последние 100 текстовых записей выбранного чата. Это ограниченное представление, без полного внутреннего журнала и скрытых рассуждений. У Desktop-чата сохраняется исходный ID; совпадение названия не доказывает, что открыт тот же чат.

Выбор модели и интенсивности проверяется по каталогу подключённого движка. При активной задаче новое сообщение направляется как уточнение этого хода; смена модели относится к следующему новому ходу.

Приём операции, завершение RPC, завершение задачи и подтверждённая остановка — разные состояния. «Остановка запрошена» не означает, что работа уже закончена. Окончание определяется событием движка, а не временем ожидания.

Карточка решения относится к конкретному чату, ходу и исходному запросу. Прочитайте команду или изменения перед разрешением. При недостаточном контексте разовое разрешение недоступно. В Mac-режиме неподдержанные и защищённые вопросы остаются в Desktop. Ответ с телефона и ответ в GUI конкурируют за один исходный запрос; ожидайте подтверждение, не нажимайте повторно.

При `unknown` или предупреждении о неопределённом исходе сначала проверьте исходный чат, состояние задачи и файлы. **Не удаляйте журнал и не повторяйте действие наугад.** Новый request ID не устраняет неопределённость предыдущей операции.

Уведомления формируются кодом по событиям; отдельная модель ради пересылки не запускается. Ошибка доставки не доказывает, что задача не выполнилась. Неуспешное уведомление не отправляется автоматически повторно; результат проверяйте в панели или Desktop.

## Прогресс и файлы

Дополнительные этапы читаются из `.task-progress/<thread>.json` в настроенной рабочей папке, если агент или ваш инструмент явно создал подходящий файл для выбранного чата. Схема — `pbc-task-status/1`. Чужой ID, неверная схема и неподходящий файл отклоняются; устаревание показывается отдельно. Этапы не создаются автоматически и не восстанавливаются по времени. Возможность записи такого файла зависит от прав текущего режима. [Реализация](../src/codex_telegram/progress.py).

К одному сообщению можно приложить до пяти загруженных файлов. Лимит файла — **10 000 000 байт**. Разрешены `txt, md, csv, json, pdf, docx, xlsx, pptx, png, jpg, jpeg, webp, gif, mp3, mp4, wav`. Поддержка загрузки формата не означает, что выбранная модель умеет его обработать.

Для выдачи поместите результат в `telegram-exports` внутри настроенной рабочей папки. Выдаются разрешённые обычные файлы верхнего уровня, без символических ссылок, до того же лимита; список ограничен 200 записями. `/get` отправляет исходные байты документом Telegram. При проблеме сохранения через WebView проверьте этот маршрут отдельно. Для целостности сравните размер и SHA-256 с оригиналом.

Файловая область общая для этой установки, а не отдельное хранилище каждого чата. Не помещайте туда документы, которые не намерены передавать через Telegram или свой HTTPS-провайдер.

## Изменить HTTPS-адрес

Остановите мост, замените placeholder своим HTTPS origin без пути и параметров.

Для Mac Desktop:

```sh
.venv/bin/python scripts/configure.py --desktop --public-url https://YOUR_ADDRESS
.venv/bin/codex-telegram-desktop run
```

Для CLI-ядра:

```sh
.venv/bin/python scripts/configure.py --public-url https://YOUR_ADDRESS
.venv/bin/codex-telegram run
```

На Windows CLI-пути — `.\.venv\Scripts\python.exe` и `.\.venv\Scripts\codex-telegram.exe`. После запуска закройте старую Mini App и откройте `/panel` заново. Quick Tunnel выдаёт временный адрес; стабильный адрес настраивается отдельно по [инструкции](INSTALL_MACOS.md).

## Настройки, токены и обновление

| Режим / ОС | Каталог по умолчанию |
|---|---|
| Mac Desktop | `~/Library/Application Support/codex-telegram-desktop` |
| CLI на macOS | `~/Library/Application Support/codex-telegram-control` |
| CLI на Windows | `%LOCALAPPDATA%\codex-telegram-control` |
| CLI на Linux | `$XDG_DATA_HOME/codex-telegram-control` либо `~/.local/share/codex-telegram-control` |

`CODEX_TELEGRAM_HOME` переопределяет каталог. Не назначайте двум режимам одну папку. В Desktop-режиме внутри находятся настройки моста и частные данные соединения, а профиль приложения остаётся прежним. В CLI-режиме дополнительно создаётся отдельный каталог `codex` с его собственными данными.

Для замены токена остановите мост и выполните команду своего режима:

```sh
.venv/bin/codex-telegram-desktop set-token
```

или, **только для CLI**:

```sh
.venv/bin/codex-telegram set-token
```

Введите новый токен скрыто, затем выполните соответствующий `doctor` и `run`. При утечке сначала отзовите токен в BotFather. В CLI дополнительно есть `forget-token`; у Desktop-команды такого подкомандного режима нет. Для удаления её записи используйте системный Keychain: service `codex-telegram-control`, account — путь именно вашей папки настроек. Не удаляйте записи других установок.

Если задан `TELEGRAM_BOT_TOKEN`, окружение имеет приоритет над Keychain. Обновите значение в используемом менеджере секретов. Не печатайте его и не вставляйте в историю команд. Удаление пакета само по себе не отзывает токен.

Перед обновлением сохраните частную резервную копию настроек после остановки моста. В Mac-режиме завершите Desktop, прежде чем менять окружение Python с используемой обёрткой. Новую версию устанавливайте в новое `.venv`, проверьте совместимость схем по RELEASE. При обновлении самого Desktop изменённый хеш вызывает отказ: порядок повторной настройки и отката — в [MACOS_DESKTOP](MACOS_DESKTOP.md). Не заменяйте хеш вручную ради снятия проверки.

Для совместимого обновления пакета на Mac распакуйте новую версию в новую папку, откройте её в Terminal и выполните:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install .
```

Не запускайте повторный `setup` поверх существующей конфигурации. Для Desktop используйте `launch`, `doctor`, затем `run` из нового окружения; для CLI — `doctor --protocol`, затем `run`. Если нужен новый каталог настроек после обновления самого Desktop, порядок отличается и описан в [MACOS_DESKTOP](MACOS_DESKTOP.md). На Windows создание CLI-окружения — `py -3.11 -m venv .venv`, установка — `.\.venv\Scripts\python.exe -m pip install .`.

## Только CLI: запуск и режим записи

После первоначального `setup` и собственного `login`:

```sh
.venv/bin/codex-telegram doctor --protocol
.venv/bin/codex-telegram run
```

На Windows используйте `.\.venv\Scripts\codex-telegram.exe`. Ctrl+C завершает этот мост и его собственный дочерний app-server. Проверка `--protocol` подтверждает локальную инициализацию, но не Telegram, телефон или ответ модели.

Смена прав выполняется после остановки CLI-моста:

```sh
.venv/bin/python scripts/configure.py --sandbox workspace-write
```

Вернуть ограниченный режим:

```sh
.venv/bin/python scripts/configure.py --sandbox read-only
```

Затем запустите `codex-telegram run`. Эти команды не меняют настройки Desktop; при Desktop-конфигурации смена sandbox запрещена.

## Диагностика

| Симптом | Следующий шаг |
|---|---|
| Подпись/версия Desktop не совпала | Остановите интеграцию, проверьте официальную сборку; не обходите проверку |
| `gateway: not_connected` | Проверьте `launch`, готовность Desktop и отсутствие неоднозначности движков |
| `codex` не найден в CLI-режиме | Проверьте отдельную установку CLI и PATH |
| Keychain/keyring недоступен | Разблокируйте хранилище своей сессии; проверьте Python и разрешённый backend |
| Конфликт polling / другая копия | Один каталог и токен обслуживает один мост; остановите прежний процесс |
| Панель не открывается / 502 | Проверьте мост, туннель, origin `http://127.0.0.1:8787` и текущий URL |
| Отказ авторизации | Откройте панель заново из своего бота; проверьте owner ID, часы и origin |
| Чат или файл не виден | Проверьте область выбранного режима и правила выдачи файлов |
| Нет уведомления | Сначала проверьте результат в исходном чате; не повторяйте неизвестную операцию |

В обращение за поддержкой включайте режим, версии и обезличенную ошибку. Не публикуйте конфигурацию, токен, `initData`, реальные ID, локальные пути, переписку и данные сокета. [Безопасность](../SECURITY.md), [реальная приёмка](MOBILE_ACCEPTANCE.md), [результаты выпуска](RELEASE.md).
