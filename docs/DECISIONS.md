# Архитектурные решения выпуска 0.2

Главный сценарий — существующие локальные чаты Codex Desktop на Mac через Telegram. Отдельное CLI-ядро и Windows Desktop-адаптер имеют собственную область применения. Решения ниже объясняют реализацию и критерии развития; живую совместимость подтверждает отдельная приёмка.

## 1. Сохранить исходный Desktop-чат и его движок

**Решение.** На Mac Desktop сам запускает свой встроенный движок через прозрачную обёртку штатного stdio. Локальный broker добавляет ограниченные операции к этому соединению. Авторизация и профиль остаются у приложения.

**Причина.** Отдельный app-server, похожая история и совпадающее название не доказывают управление уже существующим GUI-чатом.

**Последствие.** Обязательны совпадение исходного ID, отсутствие второго независимого движка и отображение результата в Desktop. Первое подключение требует штатного выхода и запуска через `codex-telegram-desktop launch`; создание нового CLI-профиля не служит fallback.

## 2. Проверить приложение и сделать запуск обратимым

**Решение.** Launcher проверяет подпись OpenAI, идентичность bundle, структуру и сохранённый хеш движка. `CODEX_CLI_PATH` задаётся только для запускаемого процесса. Файлы `.app` и глобальное окружение не изменяются.

**Причина.** Внутренний механизм Desktop может меняться. Произвольный исполняемый файл с подходящим именем не должен получать доверие приложения.

**Последствие.** Изменённая сборка требует повторной проверки. При неоднозначных движках удалённые действия блокируются. Откат возвращает обычный запуск, сохраняя профиль; проверки ОС не отключаются.

## 3. Считать внутренний контракт временной зависимостью

**Решение.** Mac-адаптер помечен кандидатом и привязан к проверяемой сборке. Статический анализ общей Darwin-ветви используется как инженерное основание, а не доказательство запуска на настоящем Mac.

**Причина.** Публичная документация app-server описывает протокол, но не гарантирует стороннее подключение к GUI. Штатный Remote Control OpenAI имеет собственный клиент и правила доступа.

**Последствие.** Apple Silicon, Intel, версии Desktop и реальные телефоны проверяются отдельно. Linux Desktop у OpenAI существует, но его подключение этим пакетом не реализовано. Обновление не получает автоматическую отметку совместимости.

## 4. Сохранить самостоятельный CLI-режим

**Решение.** Команда `codex-telegram` продолжает запускать собственный app-server с изолированным `CODEX_HOME` и своими чатами. Команда `codex-telegram-desktop` работает с существующим Desktop. Каталоги по умолчанию разные.

**Причина.** Переносимый CLI полезен независимо от GUI, однако имеет другие права, авторизацию и жизненный цикл.

**Последствие.** CLI-инструкции сохранены с явной областью. Его `login`, `doctor --protocol` и `read-only` не переносятся автоматически в Desktop-сценарий. Windows Desktop остаётся отдельным адаптером.

## 5. Один владелец и явная область доступа

**Решение.** Доступ задаётся числовым Telegram ID и проверенным `initData`. На Mac доступны локальные чаты с фактическим `cwd` внутри выбранной папки. Первый чат не выбирается вместо владельца.

**Причина.** Username, URL панели, название проекта и знание thread ID не являются достаточным основанием доступа.

**Последствие.** Worktree вне области и неподдержанные типы чатов не добавляются скрыто. Файловые маршруты ограничены отдельно. Папка выбора не заменяет sandbox инструментов.

## 6. Наследовать права Desktop, ограничивать CLI отдельно

**Решение.** Mac-мост сохраняет действующие sandbox/approval settings Desktop. CLI начинается с `read-only` и `on-request`; владелец может явно выбрать `workspace-write`.

**Причина.** Изменение разрешений чужого активного соединения нарушает ожидаемый контроль пользователя. Одобрение всех действий не исправляет транспортные ошибки.

**Последствие.** Desktop-адаптер нельзя объявлять всегда работающим только на чтение. Настройки прав меняются в Desktop; общий configure запрещает для этого режима смену sandbox.

## 7. Хранить секреты у владельца

**Решение.** Bot token находится в разрешённом системном keyring либо явно заданном окружении процесса. Локальный broker имеет закрытый Unix-сокет, проверку UID, собственный секрет и поколение соединения. В публичный пакет секреты не входят.

**Причина.** Токен и credential socket предоставляют доступ к соответствующим интерфейсам. Их передача через URL, журналы или дочернюю среду модели создаёт лишний канал раскрытия.

**Последствие.** Нет скрытого plaintext fallback или копирования авторизации Desktop. Процессы того же пользователя ОС входят в границу доверия: права файлов не защищают от уже скомпрометированной сессии.

## 8. Синхронизация кодом, действия только по точной идентичности

**Решение.** Telegram-обновления и события движка обрабатываются кодом, без служебных запросов модели ради опроса состояния. Каждая изменяющая операция получает ID и хеш до отправки.

**Причина.** Служебные модельные ходы расходуют лимиты и добавляют неопределённость. После тайм-аута действие могло выполниться, даже если ответ потерян.

**Последствие.** Неизвестный исход не становится успехом и не повторяется автоматически. Квитанция HTTP/RPC не подменяет окончание задачи. Повтор с новым ID не считается восстановлением без проверки исходного результата.

## 9. Ответить на исходный запрос ровно один раз

**Решение.** Решение связано с точными чат/ход/request и поколением. GUI и телефон конкурируют за один запрос. Разрешение требует доступного для просмотра контекста; неподдержанный или защищённый вопрос остаётся в Desktop.

**Причина.** Обычное сообщение не обязано разблокировать native approval. Два интерфейса могут ответить одновременно, а запрос — устареть при завершении хода.

**Последствие.** Различаются отправка ответа, native resolved и результат действия. При позднем подключении панель согласует уже ожидающие вопросы. Отсутствие контекста не заменяется автоматическим разрешением.

## 10. Показывать состояние только выбранного чата

**Решение.** История ограничена последними 100 текстовыми записями. Прогресс читается из явного файла текущего чата; новая задача начинает новую фазу.

**Причина.** Общая лента состояния и прежние 100% создают ложное представление о конкретном запросе. Текст истории не является журналом исполнения всех инструментов.

**Последствие.** Устаревание, потеря связи и неизвестность видны явно. Этапы не появляются сами и не рассчитываются по времени. Ограниченное представление не называется полным экспортом.

## 11. Передавать оригиналы через ограниченный файловый маршрут

**Решение.** Загрузка имеет лимит и проверку имени; результаты выдаются из `telegram-exports` рабочей области. Приёмка сравнивает исходные байты, размер и SHA-256.

**Причина.** Ссылка в тексте не доказывает наличие оригинала, а произвольный путь способен раскрыть файлы за пределами рабочей области.

**Последствие.** Доступность формата загрузки не гарантирует возможности модели. Файловая область общая для установки. Сохранение в настоящем Telegram WebView проверяется отдельно от браузерного теста.

## 12. Проверять публичный архив и реальные границы результата

**Решение.** Поставка собирается по allowlist; частные настройки, истории, журналы, ID, имена, пути и аккаунтные ссылки исключаются. Проверяется распакованный окончательный архив.

**Причина.** Рабочая папка автора содержит больше, чем исходный код. Ноль находок одного сканера не гарантирует обезличивание, а исторический тест не подтверждает новую версию.

**Последствие.** RELEASE разделяет искусственные тесты, эмуляцию и живую приёмку. Приёмка с аккаунтом пользователя, физическим телефоном и вызовом модели — **NOT_RUN**; выполненный native Mac CI описан в RELEASE. «Без изменения кода» требует готовой настройки и чистой установки, но не означает отсутствие собственных учётных данных и инфраструктуры.
