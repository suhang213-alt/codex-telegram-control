# Выпуск 0.3.0rc1: Docker и существующий Codex Desktop

Подготовлен 24 октября 2026 года. **Кандидат для приёмки**, сторонний проект под [MIT](../LICENSE). Историческая проверка 0.2.0 сохранена [отдельно](RELEASE_0.2.md); её результаты не считаются проверкой контейнерного режима.

Основной предлагаемый путь установки кандидата — Docker Compose и компонент на компьютере с Desktop. Контейнер выполняет Telegram Bot API transport и принимает запросы панели. Существующие Mac/Windows обработчики сохраняют авторизацию, область рабочих папок, решения и журнал операций. Профиль Desktop, история и рабочая папка контейнеру не монтируются. Отдельный CLI для этого режима не запускается.

Архив и образ должны иметь согласованную версию. Опубликованную строку **image@sha256:digest** берите из GitHub Release. Наличие Dockerfile не подтверждает публикацию образа. Установка — [QUICK_START](QUICK_START.md), подробности — [DOCKER](DOCKER.md).

## Проверки в GitHub

Фактические результаты каждого исходного коммита находятся в Actions:

- `Offline checks`: Windows/macOS/Linux × Python 3.11/3.12/3.13, Windows adapter и мобильная эмуляция Chromium/WebKit.
- `Signed macOS Desktop compatibility`: подпись и подключение официального Desktop на чистом Mac runner без входа и запроса модели.
- `Container build and relay smoke`: установка пакета, реальный nonroot/read-only контейнер без сети и контейнерный обмен через локальные порты с искусственным host backend; исходный request ID, авторизация, отсутствие автоповтора после потери ответа.
- `Publish reviewed Docker image`: требует успешных проверок до push, собирает `linux/amd64` и `linux/arm64`, публикует version/SHA tags и проверяет обе архитектуры в manifest. Runtime smoke исполняется на Linux amd64; arm64 подтверждается сборкой и manifest, а не отдельным исполнением.

Исходный commit, digest и ссылки на CI указываются в GitHub Release. В образ не входят CI credentials, пользовательские настройки и профили.

## Что остаётся неподтверждённым

Реальная установка Docker Desktop + авторизованный Codex Desktop на пользовательском Mac/Windows; сквозной обмен с физическим Samsung/Android или iPhone/iOS; сон, обновления и реальные системные разрешения. Доступны подготовка, CI и эмуляция. Mac Intel проверяется отдельно; Windows ARM64 и существующий Linux Desktop не заявляются.

Контейнер имеет BotFather token и является доверенной частью бота: он способен сформировать owner initData. Повторная авторизация host не защищает от вредоносного контейнера с этим токеном. Используйте проверенный digest и отдельный private-каталог. Ограничения рабочей папки и разрешения Desktop сохраняются. См. [SECURITY](../SECURITY.md) и [приёмку на устройствах](MOBILE_ACCEPTANCE.md).

## Передача и публикация

Передавайте только ссылку на Release и [инструкцию](QUICK_START.md). Каждый пользователь создаёт своего бота и вводит свои ID, токены, рабочую папку и HTTPS URL. Настройки, pair-ссылки, профиль Desktop и журналы прежней установки не копируются.

Сопровождающий проверяет изменения, обновляет версию и точный manifest, запускает `scripts/verify_release.py`, затем `scripts/build_release.py --output <новый ZIP вне репозитория>`. Для собственного fork задайте repository variable `DOCKERHUB_USERNAME` и encrypted Actions secret `DOCKERHUB_TOKEN` с правом push. Секрет не передаётся в build args. Workflow использует явный version tag; `latest` не используется.
