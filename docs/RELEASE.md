# Выпуск 0.2.0: существующие чаты Desktop на macOS

Подготовлен 24 октября 2026 года. **Кандидат для приёмки**, сторонний проект под [MIT](../LICENSE).

## Что изменилось

Основной сценарий Mac теперь использует движок, запущенный самим Desktop, и оригинальные идентификаторы чатов. Отдельный app-server или копия профиля для этого режима не создаются. Доступ ограничен выбранной рабочей папкой. Поддержаны история, продолжение и остановка текущего хода, вопросы, разовые разрешения и файлы. Настройки прав остаются в Desktop.

Установщик проверяет официальную подпись приложения; конфигурация фиксирует установленную версию и хеш движка. Подключение выполняется через локальный Unix-сокет с секретом текущего пользователя. Обновление приложения требует повторной настройки. При неоднозначном движке, потере событий или неизвестном исходе операции мост прекращает удалённые действия до проверки владельцем.

Windows-адаптер сохранён отдельно. На Linux поставляется самостоятельный CLI-режим; управление существующим Linux Desktop здесь не реализовано. Apple Silicon/Intel и реальные мобильные клиенты требуют приёмки на соответствующих устройствах.

## Проверки и доказательства

Локальная среда: Windows x64, Python 3.12.14. Тестовые данные искусственные. Команды и границы проверок:

| Проверка | Что проверяется |
|---|---|
| `python -B scripts/test_offline.py` | Переносимое ядро, macOS launcher, broker, DesktopController/RPC; внешняя сеть и посторонние дочерние процессы запрещены guard-проверкой |
| `python adapters/windows_desktop/scripts/test_offline.py` | Отдельный Windows-адаптер на искусственных данных |
| Сборка wheel и установка в чистую среду | 13 проверок пройдены: сборка без сети, установка без зависимостей, точки входа, импорт модулей, безопасный отказ macOS doctor на другой ОС |
| Мобильная панель, режим Desktop | 3 профиля экрана, по 18 групп проверок; Chromium через Edge 156.0.4314.42, Playwright 1.62.1 |
| GitHub Actions | Матрица Windows/macOS/Linux × Python 3.11/3.12/3.13, два режима панели в Chromium/WebKit, Windows-адаптер; фактический результат каждого коммита находится во вкладке Actions |
| Signed macOS Desktop compatibility | Отдельный Mac runner скачивает официальный DMG, проверяет подпись, запускает Desktop с пустым профилем и проверяет подключение через наш адаптер; вход в аккаунт и запросы модели отсутствуют. Результат — отдельная квитанция workflow, отказ не считается успехом |

Точные локальные счётчики находятся в [VALIDATION.json](VALIDATION.json). Отдельные прогоны не объединены в вымышленную сквозную приёмку. Исходники в архиве сверяются по [манифесту](../MANIFEST.json). После изменений повторяются затронутые проверки.

Мобильная эмуляция охватывает 360×780, 412×915 и 390×844, уменьшенную область при клавиатуре, отправку текста, решения, оригинальный ID чата, файлы, изоляцию чатов и отображение недоверенного текста. Telegram SDK и backend подменены. Реальные Telegram, Samsung WebView, iOS и системное хранилище токена в этих тестах не использовались. Проверка подписанного Desktop выполняется отдельным workflow; GitHub runner не имеет авторизованного Desktop пользователя. В его артефакт включается только обезличенная квитанция; временный профиль исчезает вместе с одноразовой машиной.

**Не подтверждено:** чистая установка с настоящим аккаунтом, реальный обмен Mac ↔ Telegram ↔ Samsung, Intel/Apple Silicon, сон и обновление приложения, системные разрешения. Чек-лист — [MOBILE_ACCEPTANCE](MOBILE_ACCEPTANCE.md). Успешный CI не означает приёмку этих сценариев. Универсальная гарантия работы на любых ОС и устройствах не заявляется.

## Передача пользователю

Передайте ссылку на этот репозиторий или GitHub Release. Первый пользователь открывает [INSTALL_MACOS](INSTALL_MACOS.md), скачивает исходный ZIP и вводит **свои** данные при настройке. Изменение исходников не требуется. Компьютер, Desktop, мост и HTTPS-туннель должны работать во время использования телефона.

Не передавайте настройки прежнего владельца, его бота, токен, Telegram ID, профиль Desktop, историю, рабочую папку или журналы. Каждый пользователь создаёт собственного бота и использует свой аккаунт Codex. Хранилище данных находится вне исходного пакета; подробнее — [SECURITY](../SECURITY.md).

## Сборка и публикация сопровождающим

В публичную поставку входят только проверенные файлы из манифеста и сам манифест. Частные отчёты, переписка, конфигурации, бинарники и история рабочего проекта исключены.

```sh
python3 -B scripts/verify_release.py
python3 -B scripts/build_release.py --output ../codex-telegram-control-0.2.0-candidate.zip
```

Сборщик требует новый путь за пределами репозитория, проверяет состав, CRC и записывает SHA-256. После распаковки снова выполните `scripts/verify_release.py`. Хеш подтверждает целостность; доверие к источнику скачивания проверяется отдельно.

Для первого размещения используется новый пустой репозиторий и новая история Git. Публикуйте только эту папку, дождитесь проверок Actions, создайте pre-release `v0.2.0-candidate` с исходным ZIP и `.zip.sha256`. Для следующей версии сначала проверьте изменения, конфиденциальность и тесты, затем обновите версию и манифест. Простая замена хешей не заменяет проверку содержимого.

## Отбор решений

Предыдущие технические ветки проекта использованы как материал исследования: проверены доступная история решений, текущие модули и связанные тесты. Полное чтение каждого служебного вывода не заявляется. Личные настройки и облачные адреса не переносились. В новую поставку вошли ограничение области чатов, явные решения владельца, защита от повторов при неизвестном результате, оригинальные файлы и прогресс только выбранного чата. Порядок развития — [DEVELOPMENT](DEVELOPMENT.md), основания — [DECISIONS](DECISIONS.md).
