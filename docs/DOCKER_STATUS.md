# Docker Hub: состояние подготовки

Этот документ относится к будущему выпуску. Текущий Dockerfile проверяет только установку Python-пакета в Linux-контейнер. **Он не запускает бота и не управляет существующими чатами Codex Desktop.** На Docker Hub образ ещё не опубликован; Docker не является основным способом установки текущего выпуска.

## Почему нужен компонент на компьютере

Подписанное приложение Codex Desktop и его движок выполняются в пользовательской сессии macOS или Windows. Mac-адаптер проверяет подпись приложения, UID клиента и локальный Unix-сокет. Windows-адаптер использует процесс Desktop, Windows IPC и DPAPI. [Docker Desktop выполняет Linux-контейнер в виртуальной машине](https://docs.docker.com/desktop/features/networking/); настройка томов или сети сама по себе не переносит эти проверки и API. Подмена их отдельным CLI создала бы другие чаты и нарушила основной сценарий продукта.

Целевая схема: контейнер содержит Telegram-бота и Mini App; локальный компонент на компьютере проверяет и обслуживает существующий Desktop через текущий адаптер. Компонент подключается к контейнеру через отдельный ограниченный канал с проверкой подлинности. Профиль Desktop, ключи, токен его внутреннего шлюза и произвольный доступ к shell не передаются контейнеру. Контроллер на компьютере сохраняет проверку рабочей папки, исходных ID и журнал операций; неизвестный результат не повторяется автоматически.

До объявления Docker основным способом запуска нужны: работающие компоненты для Windows и macOS, контейнерные секреты без записи в образ, проверка запуска на обеих ОС, мобильная приёмка, опубликованный и проверенный digest Docker Hub. Текущая подготовительная сборка в CI этих условий не подтверждает.

Публикация в личный namespace Docker Hub требует точного имени аккаунта и настроенного доступа CI с правом push. [Официальный порядок сборки и push через GitHub Actions](https://docs.docker.com/guides/gha/) использует учётные данные, сохранённые в настройках CI. Значения токенов не публикуются в репозитории и не вставляются в issue или чат.
