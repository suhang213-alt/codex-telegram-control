# Порядок разработки и приёмки

В выпуске 0.2 главный сценарий — управление существующими локальными чатами Mac Desktop. Отдельное CLI-ядро и Windows-адаптер сохраняются как самостоятельные режимы. Их результаты проверок нельзя переносить друг на друга. [Архитектурные решения](DECISIONS.md), [границы безопасности](../SECURITY.md).

## Карта реализации

| Область | Основные файлы |
|---|---|
| Mac: поиск приложения, подпись, запуск и откат | `src/codex_telegram/macos_platform.py`, `macos_cli.py` |
| Штатный поток Desktop и локальный broker | `desktop_gateway.py`, `desktop_rpc.py` |
| Существующие чаты Desktop | `desktop_controller.py` |
| Отдельное CLI-ядро | `cli.py`, `rpc.py` |
| Общие действия, вопросы, история и файлы | `controller.py` |
| Telegram, HTTP и проверка доступа | `telegram.py`, `server.py`, `security.py` |
| Панель и явный прогресс | `static/`, `progress.py` |
| Windows Desktop | `adapters/windows_desktop/` |

Указанные имена относятся к `src/codex_telegram/`, кроме отдельно указанного адаптера. Конфигурации, истории и данные пользователя не являются исходниками.

## 1. Зафиксировать сценарий и доказательство результата

Перед изменением запишите конкретную проблему, режим, версию внешнего приложения и ожидаемое наблюдаемое поведение. Для Mac ключевой критерий: сообщение приходит в **исходный Desktop-чат с тем же ID через его движок**. Похожее название, копия истории или работа отдельного CLI этого не доказывают.

Различайте факт чтения кода, искусственный тест, интеграционный тест и реальное устройство. Для неподтверждённого поведения задайте критерий приёмки; не превращайте гипотезу в обещание совместимости.

## 2. Подготовить изоляцию разработки

Используйте временные каталоги, искусственные сообщения, файлы и протокольный процесс. В offline-тестах запрещайте внешние подключения и неподтверждённые дочерние процессы. Не запускайте настоящий Desktop, Telegram-поллинг или модель ради проверки единичной функции.

Пользовательские настройки находятся вне репозитория. Токен нельзя включать в URL, shell history, аргументы, фикстуры или дочернюю среду модели. Проверяйте Unicode и пробелы в путях; код не должен знать путь, ID или аккаунт автора.

Критерий: тесты воспроизводимы в новой временной папке без профиля разработчика.

## 3. Подтвердить установленный Desktop и обратимость запуска

Сначала проверяются подпись, bundle identity, структура исполняемых файлов и хеш встроенного движка. Отдельно проверяются идентичность родительского процесса и текущий пользователь. Уже открытый Desktop закрывает владелец штатно; launcher не подменяет окружение существующего процесса.

Обёртка включается только для нового процесса приложения. Не изменяйте `.app`, глобальные переменные, подпись, TCC или sandbox. Откат должен запускать прежний Desktop без обёртки, сохраняя профиль и чаты.

Критерий: неподписанная, изменённая или неоднозначная установка отклоняется; обычный запуск восстанавливается. Искусственная проверка этих ветвей не заменяет реальную macOS-проверку.

## 4. Сохранить штатный транспорт до добавления функций

Desktop остаётся владельцем движка и его initialize/initialized. Мост не создаёт второй app-server, не повторяет initialize и не использует отдельный профиль как скрытый fallback.

Сохраните точные аргументы, окружение, cwd, байты штатных сообщений и корректное завершение процессов. Инъекции моста должны иметь собственное пространство ID; их ответы не должны попадать GUI как чужие ответы. Неизвестный тип штатного сообщения не даёт права менять его смысл.

Проверьте порядок ответов, частичные записи, сообщения больше внутреннего буфера, разделение JSONL-кадров, тайм-аут и поздний ответ. Инъекция между частями одного штатного кадра недопустима. При неоднозначности нескольких движков блокируйте удалённые действия, сохраняя работу исходного клиента.

Критерий: byte-for-byte passthrough на тестовых кадрах, отсутствие второго initialize, отсутствие повреждений при конкурентном RPC. Непроверенная граница размера фиксируется явно.

## 5. Добавить доступ и журнал до мобильного UI

Локальный broker проверяет владельца Unix-соединения, секрет и поколение. HTTP API имеет ограниченный список действий, а не произвольный RPC. Telegram-вход требует numeric owner ID, личный чат и подлинный свежий `initData`.

Desktop-чат допускается по фактическому `cwd` внутри выбранной области. Проверяйте принадлежность перед изменяющим действием; одного сохранённого списка недостаточно. До первого явного выбора чат не назначается автоматически.

Перед отправкой записывайте ID операции и хеш содержимого. Повтор ID с другим содержимым отклоняется. Неизвестный исход нельзя повторять с новым ID автоматически. Квитанция RPC и завершение модельной задачи имеют разные состояния.

Критерий: чужой запрос, поддельный чат, устаревшее соединение и повтор после сбоя не дают лишнего исполнения.

## 6. Подключить существующий чат и согласовать состояние

Последовательность Mac-сценария: разрешённый список → явный выбор → история → обычное сообщение → уточнение активного хода → остановка. Новый чат создаётся в Desktop.

После получения области чатов согласуйте текущие активные ходы и pending requests с состоянием broker. Разрешение могло появиться до подключения панели или до определения `cwd`; его нельзя потерять при начальном фильтре. Повторная синхронизация не должна создавать дубликаты карточек.

Не держите общий lock во время длительного ожидания RPC или чтения всей истории. Очереди и история ограничены; переполнение вызывает видимое требование восстановления, а не молчаливую потерю решения.

Критерий: одинаковый исходный ID до/после, одна отправка, правильный активный ход, согласование вопросов при позднем подключении моста.

## 7. Встроить вопросы и разрешения

Поддерживайте явный список native requests. Неизвестные и защищённые запросы Desktop остаются у оригинального клиента; мост не отвечает на них автоматической ошибкой от имени GUI. Сохраняйте точные ID чата, хода, запроса и варианты вопроса.

Для разового разрешения нужны полные сведения о рассматриваемой команде или изменениях. Недостаток контекста блокирует разрешение, сохраняя безопасный отказ или работу в Desktop. Ответ с Mac и телефона должен иметь единственного победителя.

Проверяйте три отдельных факта: ответ отправлен, исходный запрос разрешён сервером, сама операция завершена. Кнопка на телефоне не является подтверждением всех трёх.

Критерий: безопасный запрос → единственный точный ответ → native resolved → фактический результат; отдельно гонка GUI/телефон, просроченный ID, иной ход, скрытый ввод и неполный контекст.

## 8. Добавить файлы, прогресс и мобильный интерфейс

Файлы принимаются и выдаются в ограниченной рабочей области. Проверяйте реальный путь, перенаправляющие ссылки, имя, лимиты, Unicode и исходные байты. Файловая область общая для установки; не заявляйте изоляцию каждого чата, если её нет.

Прогресс текущего чата читается из явного статус-файла. Старое завершение не переходит в новый ход. Нельзя вычислять готовность по ожиданию или подставлять статус другой задачи.

Мобильная эмуляция проверяет геометрию, текст, клавиатурный viewport и действия с подменённым API. Настоящие Telegram initData, Samsung WebView, загрузки и сон Mac требуют отдельного испытания.

Критерий: на узком экране доступны история, решение и ввод; вредоносный текст не исполняется; при смене чата данные не смешиваются. [Чек-лист устройств](MOBILE_ACCEPTANCE.md).

## 9. Сохранить отдельное CLI-поведение

CLI-режим запускает собственный app-server через stdio, создаёт отдельный `CODEX_HOME` и использует только свои чаты. Его начальные права — `read-only` и `on-request`; `workspace-write` выбирается явно.

Mac Desktop наследует действующие настройки GUI и не использует CLI sandbox-конфигурацию. Изменение общего контроллера проверяется в обоих режимах: ответ, допустимый для собственного CLI-процесса, может быть недопустим для потока, которым владеет Desktop.

Критерий: отдельные каталоги, команды и жизненный цикл; остановка Desktop-моста не завершает приложение. Ошибка Desktop-подключения не переключает пользователя молча на новые CLI-чаты.

## 10. Выполнить проверки по слоям

Из корня репозитория, с Python 3.11+:

```sh
python3 -B scripts/test_offline.py
```

На Windows используйте `python` из нужного окружения. Набор использует искусственный протокольный процесс и временное состояние; внешняя сеть и неожиданные дочерние процессы блокируются.

Проверка интерфейса:

```sh
npm install
npx playwright install chromium
node tests/mobile_smoke.cjs
```

Скачивание зависимостей выполняется до теста. Сценарий UI использует подменённый Telegram/backend; выбор WebKit и установленных браузеров описан в [MOBILE_ACCEPTANCE](MOBILE_ACCEPTANCE.md).

Windows-адаптер проверяется отдельно с Python 3.12:

```powershell
py -3.12 adapters/windows_desktop/scripts/test_offline.py
```

Не называйте этот прогон подключением к живому Desktop. После затронутых тестов проведите независимую рецензию авторизации, транспортного потока, гонок, восстановления и защиты данных. Самопроверка автора независимой рецензией не считается.

## 11. Проверить настоящие устройства и восстановление

На конкретных Mac/сборке Desktop проверьте исходный ID, единственный движок, историю, обмен, разрешения, остановку, перезапуск, сон, смену URL и откат. Apple Silicon и Intel учитываются отдельно. Samsung и iOS — разные прогоны. Проверка одной ОС не подтверждает все остальные.

Приёмка с аккаунтом пользователя, физическим телефоном и вызовом модели имеет статус **NOT_RUN**. Выполненный native Mac CI подтвердил запуск официального Desktop и ответ на запрос списка чатов без входа в аккаунт; результаты и границы проверки приведены в RELEASE. Данные будущей приёмки включаются в RELEASE только после фактического запуска.

## 12. Собрать и проверить публичный объект

Собирайте по allowlist: исходники, инструкции, лицензия, синтетические тесты и необходимые конфигурации разработки. Исключайте профиль, токены, настройки, session/operation files, рабочие документы, персональные URL/ID/пути, снимки, кэши и `.pyc`.

Проверьте тексты, фикстуры, комментарии, метаданные и состав архива. Контрольная сумма подтверждает неизменность, а не безопасность. Распакуйте окончательный ZIP в новую папку и проверьте именно его. Старый манифест после изменения кода должен перестать совпадать; простое обновление хешей не заменяет приёмку.

Порядок сборки и публикации — [RELEASE](RELEASE.md). Не запускайте публикацию из личного рабочего каталога.

## Что фиксировать в результате

| Проверка | Обязательное свидетельство |
|---|---|
| Код | Версия/хеш, команда, pass/fail/skip, причины пропусков |
| Протокол | Реальный либо искусственный peer; охват framing, решений и ошибок |
| Mac Desktop | ОС, архитектура, версия приложения; совпадение ID и движка без публикации частных значений |
| Телефон | Модель, ОС, Telegram/WebView, клавиатура и оригинальный файл |
| Восстановление | Что именно отключалось или перезапускалось |
| Сеть и модель | Были ли внешние соединения и настоящий вызов |
| Архив | Состав, хеш, проверка распакованной копии, ограничения privacy-проверки |

«Без изменения кода» означает предусмотренную установку и пользовательскую настройку. Нужны собственные аккаунт, бот и HTTPS-инфраструктура. Готовность к эксплуатации объявляется после чистой установки и применимой приёмки, а не по историческому успеху другого экземпляра.
