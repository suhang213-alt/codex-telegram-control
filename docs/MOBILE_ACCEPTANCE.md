# Приёмка: Mac Desktop и Telegram на телефоне

Разделены три уровня проверки: код на искусственных данных, браузерная эмуляция, настоящее приложение и телефон. Успех первого или второго уровня не подтверждает третий. На момент подготовки пакета реальная приёмка Mac + Samsung не выполнялась; фактические прогоны перечислены в [RELEASE](RELEASE.md).

## Проверки без настоящего аккаунта

Из корня репозитория:

```sh
python3 -B scripts/test_offline.py
npm install
npx playwright install chromium
node tests/mobile_smoke.cjs
```

Python-проверка использует искусственный протокольный процесс, блокирует внешнюю сеть и неподтверждённые дочерние процессы. Она не запускает Desktop или модель. Установка npm-зависимостей и браузера требует сети; браузерный сценарий подменяет API приложения и Telegram.

Smoke-тест проверяет размеры 360×780, 412×915 и 390×844, а затем уменьшенный viewport для экранной клавиатуры. Проверяются доступность ввода и отправки, длинная история, прокрутка, отсутствие горизонтального выхода, защита от исполнения враждебного текста, вопросы, разрешения, переключение чатов и получение искусственного файла. Уменьшение viewport не воспроизводит всю механику клавиатуры Telegram WebView.

По умолчанию используется Chromium Playwright. Можно выбрать уже установленный тестовый браузер, без рабочего профиля пользователя:

```sh
MOBILE_BROWSER_CHANNEL=chrome node tests/mobile_smoke.cjs
```

В PowerShell для имеющегося Edge:

```powershell
$env:MOBILE_BROWSER_CHANNEL = 'msedge'
node tests/mobile_smoke.cjs
```

`MOBILE_BROWSER_EXECUTABLE` задаёт исполняемый файл явно. Для профиля iPhone в WebKit установите `npx playwright install webkit` и запустите с `MOBILE_USE_WEBKIT=1`. Без этого проверяется только размер iPhone в Chromium. Отсутствие выбранного браузера — ошибка, а не пройденная проверка.

Отчёт и синтетические снимки находятся в `.test-results/mobile/`; путь меняется через `MOBILE_REPORT_DIR`. Отчёт должен указывать реальный движок и версию. Не называйте эмуляцию проверкой настоящего Samsung, Safari или iPhone.

## Короткая проверка существующего чата

После [настройки](INSTALL_MACOS.md) выполните этот сценарий на настоящих устройствах. Сам обмен обычно занимает около минуты; установка, получение ответа и восстановление после сбоев в эту оценку не входят.

1. В Desktop откройте существующий тестовый чат с искусственной историей. До подключения запишите его точный ID локально из ссылки или сведений приложения, если версия их предоставляет. Одного названия недостаточно.
2. После `launch` и успешного `doctor` зафиксируйте встроенный процесс движка, принадлежащий этому Desktop. Запустите `run`: новый независимый app-server для бота не должен появиться; исходный движок продолжает использоваться. Сравнение выполняется локально средствами просмотра процессов, без публикации их полных аргументов.
3. На телефоне выберите этот чат. Откройте настройки панели и сравните показанный ID с исходным. Старая история должна присутствовать.
4. Отправьте один раз: «Ответь только ПРОВЕРКА-ГОТОВО. Файлы не меняй». Проверьте одно пользовательское сообщение и один ответ в том же чате Desktop и на телефоне.
5. Снова сравните ID и убедитесь, что отдельного чата с таким же названием не появилось.

Это настоящий вызов модели и расход лимитов. Если ID исходного чата надёжно получить нельзя, соответствующий пункт остаётся «не выполнялся»: сходство истории не заменяет точное сравнение. В публичном отчёте пишите только «ID совпал / не совпал»; сами ID и переписку не публикуйте.

## Полная проверка Mac-адаптера

Используйте отдельную тестовую рабочую папку. Для каждой строки фиксируйте «пройден», «нарушен» либо «не выполнялся» с причиной.

| Сценарий | Ожидаемый результат |
|---|---|
| Область доступа | Видны подходящие локальные чаты; чат вне выбранной папки и архивный чат недоступны |
| Нет выбора | До явного выбора нельзя случайно отправить сообщение в первый чат списка |
| Идентичность | Сохраняются исходный ID и история, нет второго независимого движка |
| Ответ на вопрос | Кнопка и свободный ответ в отдельных поддерживаемых вопросах закрывают исходный запрос в Desktop |
| Отказ | Отказ на телефоне закрывает соответствующий запрос; действие не разрешается |
| Разрешение | Для безопасной тестовой операции доступен полный контекст; выполняется только явно разрешённое действие |
| Нет контекста | При недоступной команде или изменениях кнопка разрешения заблокирована |
| Ответ с Mac и телефона | Ответьте почти одновременно в обоих интерфейсах; применяется один ответ, второй не выполняется повторно |
| Защищённый ввод | Секрет запрашивается и вводится на Mac; телефон не получает поле для его передачи |
| Остановка | `/stop` останавливает именно выбранную активную задачу; итог подтверждается в Desktop |
| Перезапуск моста | Ctrl+C не закрывает Desktop; новый `run` восстанавливает доступ к тем же чатам |
| Перезапуск Desktop | Старое соединение становится недействительным; новый `launch`, `doctor`, `run` не воспроизводят прежние команды |
| Сон и сеть | После сна/разрыва видно отсутствие подтверждённой связи; после восстановления нет повторной отправки |
| Обновление / подпись | Неожиданная идентичность или изменённый движок приводят к отказу; защита ОС не отключается |
| Откат | После `rollback` обычный Desktop открывает прежние чаты без подключения бота |

Проверки отказа подписи и повреждённого приложения сначала выполняйте на искусственных тестовых данных. Не изменяйте установленную подписанную `.app` ради теста. Настоящее обновление и повторную настройку фиксируйте как отдельный сценарий совместимости.

Если установленная версия не создаёт определённый тип вопроса или разрешения, не подменяйте его похожим текстовым сообщением. Отметьте сценарий непроверенным. Не повышайте права Desktop только ради получения разрешения в тесте.

## Проверка Samsung / Android

1. Запишите модель телефона, Android, Telegram, масштаб шрифта и ориентацию экрана. IMEI, номер телефона, Telegram ID и личные снимки в отчёт не включайте.
2. Откройте панель из собственного бота. Проверьте доступ владельца и отказ постороннему тестовому пользователю.
3. Прокрутите длинную искусственную историю, вызовите клавиатуру, введите многострочный текст, сверните и верните клавиатуру, поверните телефон. Поле ввода и отправка должны оставаться доступны.
4. Переключите два тестовых чата. История, вопросы, статус и прогресс не должны смешиваться. Повторное открытие панели не возвращает старое завершение в новую задачу.
5. Загрузите разрешённый искусственный файл до 10 MB и отправьте его один раз. Проверьте наличие файла в рабочей папке. Слишком большой файл должен быть отклонён.
6. Получите небольшой файл с Unicode-именем из `telegram-exports`. Откройте его в «Мои файлы», сравните размер и SHA-256 с оригиналом. Если WebView не сохраняет файл, отдельно проверьте `/get имя_файла`; обходной способ не превращает неработающую кнопку загрузки в успех.
7. Отключите и восстановите сеть во время синтетической операции. При неизвестном результате сначала проверьте исходный чат на Mac. Убедитесь, что повтор не отправился автоматически.
8. Закройте и заново откройте Mini App после длительного перерыва: новый сеанс должен пройти проверку Telegram; устаревшая авторизация не должна действовать бессрочно.

Для iOS повторите отдельный прогон на настоящем устройстве. Результат Android не подтверждает iOS, а Telegram Desktop на Mac не подтверждает Telegram на телефоне.

## Протокол результата

Зафиксируйте версию пакета и хеш архива, версию Desktop, macOS и архитектуру, Python, Telegram, модель тестового устройства, сценарий, результат и причину пропуска. Отдельно укажите, были ли внешний Telegram, настоящий движок и вызов модели. Сохраняйте только обезличенные доказательства.

«Готово для Mac + Samsung» допустимо после всех применимых обязательных сценариев без необъяснённых пропусков. До этого корректно: **«код и эмуляция проверены в указанном объёме; реальная совместимость ещё не подтверждена»**. Успешная проверка одной версии Desktop не гарантирует совместимость после обновления.
