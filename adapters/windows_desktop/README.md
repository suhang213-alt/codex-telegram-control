# Необязательный адаптер существующих чатов Codex Desktop

Этот каталог сохраняет расширенный Windows-мост: чат и вложения, история, квитанции доставки, отдельный прогресс выбранной задачи, решения владельца и Mini App. Основной переносимый режим проекта находится в корне репозитория. Для одного токена запускайте только один polling-процесс.

**Граница совместимости:** Windows x64, Python 3.12, установленный и авторизованный Codex Desktop с доступным bundled `codex-app-tools`. Native MCP, локальная база Desktop и перехват его stdio — внутренние интерфейсы приложения. Они не являются универсальным публичным API. Обновление Desktop может потребовать обновления этого адаптера; запуск блокируется при неуспешном compatibility check. Linux, macOS и Windows ARM64 для этого дополнительного адаптера не заявляются.

## Настройка

Из корня скачанного репозитория:

```powershell
py -3.12 adapters/windows_desktop/scripts/setup.py
py -3.12 adapters/windows_desktop/scripts/doctor.py
py -3.12 adapters/windows_desktop/scripts/doctor.py --native
py -3.12 adapters/windows_desktop/scripts/pair.py
py -3.12 adapters/windows_desktop/scripts/start.py
```

`setup.py` запрашивает числовой Telegram user ID, UUID отдельного существующего локального служебного чата, разрешённую рабочую папку, Codex home и установленный bundled plugin. UUID — контекст маршрутизации; служебные model turns не создаются. Если в cache несколько версий plugin, выберите установленную совместимую версию явно: самый большой номер версии сам по себе не доказывает совместимость. Числовой user ID необходимо получить из доверенного источника, например проверенного события Telegram для собственного аккаунта; username не заменяет ID.

Токен вводится через скрытый ввод и хранится с Windows DPAPI текущего пользователя. Настройки, очередь и вложения находятся в `%LOCALAPPDATA%/CodexTelegramDesktop`, вне репозитория. `CTD_DATA_DIR` допускает отдельный каталог для изолированных установок. Бот принимает только личный чат настроенного числового владельца после одноразовой привязки; смена username не меняет полномочий.

В настройке можно явно включить HTTPS-туннель `localhost.run`; требуется установленный OpenSSH. По умолчанию туннель выключен. Без публичного HTTPS Telegram Mini App с телефона недоступен: бот продолжает работать, страница локального сервера не обходит Telegram-аутентификацию. Туннель передаёт трафик стороннему оператору и работает, пока включён компьютер. Автоматическая установка зависимостей и tunnel-бинарников отсутствует.

`doctor.py` проверяет локальные предпосылки без обращения к Telegram. `--native` выполняет только handshake и получение каталога native tools, без вызова модели. `start.py` повторяет эту проверку перед polling. Запуск остаётся в текущем терминале; остановка — **Ctrl+C**. Автозагрузка и задачи Windows этим комплектом не создаются.

## Ответы на настоящие запросы разрешений Desktop

Обычный native MCP не даёт универсального способа ответить на ожидающий stdio approval исходного Desktop. Для этой возможности предусмотрен дополнительный shim, который сохраняет исходные ID запросов, текущую connection epoch, sandbox и реальный Desktop engine. Он не создаёт разрешений от имени владельца.

Сначала при обычном работающем Desktop определите PID именно дочернего `codex.exe app-server`. Затем:

```powershell
py -3.12 adapters/windows_desktop/gateway/build.py --engine-pid <PID>
```

Сборка проверяет, что родитель engine — зарегистрированный Codex Desktop в той же Windows-сессии, сохраняет только два allowlisted sandbox-параметра и hash исходного CLI. Нужен локальный .NET Framework C# compiler. Сборка не запускает Desktop и не меняет системные переменные. Результат остаётся в локальном каталоге данных; исполняемые файлы и персональная конфигурация сборки не публикуются.

Сохраните работу, завершите активные задачи и штатно закройте Desktop. Затем явно активируйте:

```powershell
py -3.12 adapters/windows_desktop/gateway/activate.py
```

Запуск передаёт `CODEX_CLI_PATH` только новому процессу Desktop. Если Desktop уже открыт, активация откажет; процессы не завершаются принудительно. Оригинальный CLI не заменяется. После запуска повторите `doctor.py --native` и проверьте одну искусственную задачу: запрос разрешения должен совпасть в Desktop и Telegram, ответ владельца — получить подтверждение сервера, повторное нажатие — не повторить действие. Этот live-check не заменён offline-тестами.

Для отката штатно закройте Desktop и выполните:

```powershell
py -3.12 adapters/windows_desktop/gateway/activate.py --rollback
```

После обновления Desktop повторная сборка обязательна. Если engine уже запущен через shim, сначала выполните откат: build требует непосредственного проверенного родителя Desktop.

## Защита и ограничения

- Доступ к существующему чату подтверждается по локальной metadata-базе и разрешённой рабочей папке; `cwd` из запроса не принимается на доверии. Чаты вне allowlist скрыты и недоступны для действий.
- Пакет не публикует журналы, профили, личные пути, tokens, реальные user/chat IDs, runtime-файлы или предыдущие настройки. Примеры и тестовые идентификаторы искусственные.
- Mini App проверяет подпись Telegram initData, числового владельца, дубликаты полей и срок один час. Секретные ответы и непредставимые запросы остаются в Desktop.
- Неопределённый исход мутации не приводит к автоматическому повтору. «Принято в очередь» отличается от подтверждённого ответа.
- Облачные connector/gateway сценарии, ChatGPT cloud chats, частные проектные доски и corpus dashboards в этом адаптере отключены. Остаточные compatibility-модули не являются настроенным облачным сервисом.
- Голосовая транскрипция не включена: нужны отдельные локальные optional ASR-зависимости и модель. Отсутствующий ASR не должен считаться успешной расшифровкой.
- Полная проверка на каждом Desktop build и личном Telegram аккаунте остаётся локальной приёмкой владельца установки. Offline-тесты не доказывают доступность закрытого Desktop API.

## Проверка и удаление

```powershell
py -3.12 adapters/windows_desktop/scripts/test_offline.py
py -3.12 adapters/windows_desktop/scripts/uninstall.py
```

Тесты создают отдельные `CTD_DATA_DIR`, `LOCALAPPDATA`, `CODEX_HOME`; сеть и запуск внешних программ заблокированы. Multiprocessing workers используют только искусственные данные журналов. Для удаления локальных данных после остановки: `uninstall.py --delete-local-data`. Пользовательский `CTD_DATA_DIR` автоматически рекурсивно не удаляется; его содержимое следует проверить вручную. Codex-профиль и переписка Telegram не удаляются.
