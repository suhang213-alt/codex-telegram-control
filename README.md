# Telegram для существующих чатов Codex Desktop

Личный Telegram-бот и Mini App для продолжения **существующих локальных чатов Codex Desktop**. Mac и Windows используют свои native-адаптеры; на телефоне нужен Telegram Android или iOS. Работа выполняется на компьютере пользователя.

**Основной предлагаемый запуск кандидата 0.3.0rc1 — Docker Compose и native-компонент компьютера:** [короткие команды Windows/macOS](docs/QUICK_START.md), [подробная инструкция Docker](docs/DOCKER.md). Образ и его digest берите из соответствующего GitHub Release; `package-check` рабочим ботом не является.

Первый запуск на **Windows + Samsung Galaxy**: [что скачать, куда нажать и какие команды вставить](docs/WINDOWS_SAMSUNG_DOCKER.md). В инструкции приведены все параметры Docker, порты, секреты и проверка результата.

**Статус: кандидат для приёмки.** Реальная связка Docker Desktop + авторизованный Desktop + физический Samsung/iPhone ещё не проверена. Прежний native Mac-адаптер проходил контрольный запуск подписанного Desktop 26.1021.31345 в GitHub без входа и модели; это отдельное свидетельство, не приёмка нового Docker-сценария. Результаты и ограничения — в [RELEASE](docs/RELEASE.md).

Mac-адаптер подключается к движку, который запускает сам Desktop. Для подключения нужно штатно закрыть приложение и запустить его командой пакета. Дополнительный Codex CLI, отдельный вход или копия профиля для этого режима не нужны. Обычные облачные беседы ChatGPT и удалённые хосты этим адаптером не подключаются.

## Возможности и границы

| Среда | Что предоставляет пакет | Статус |
|---|---|---|
| macOS, Apple Silicon | Существующие локальные чаты Desktop в выбранной рабочей папке | Запуск и подключение проверены в CI; приёмка с аккаунтом ещё нужна |
| macOS, Intel | Тот же сценарий при совместимой официальной сборке Desktop | Кандидат; реальной проверки Intel нет |
| Windows Desktop | Отдельный [Windows-адаптер](adapters/windows_desktop/README.md) | Кандидат; требуется проверка совместимости установленной версии |
| Linux | Отдельные чаты переносимого CLI-ядра | Подключение Linux Desktop в этом пакете не реализовано |
| Telegram Android / Samsung | Бот и Mini App | Есть эмуляция интерфейса; реального устройства не было |
| Telegram iOS | Та же веб-панель | Есть эмуляция интерфейса; реальное устройство iOS не проверялось |

Совместимость установленного Desktop проверяется командами native `doctor` и текущей приёмкой. Доступность приложения на какой-либо ОС сама по себе не подтверждает поддержку этим адаптером. Контейнерные архитектуры `linux/amd64` и `linux/arm64` также не означают управление существующим Linux Desktop.

Панель показывает локальные неархивные чаты, рабочая папка которых находится внутри выбранной области. Название проекта само по себе не задаёт доступ. Чаты worktree за пределами этой папки не появятся. Показываются последние 100 текстовых записей; это не полный экспорт истории, вложений и служебных событий.

Доступны выбор модели и интенсивности из текущего каталога, ответ на поддерживаемый вопрос, отказ или разовое разрешение с доступным для просмотра контекстом. Защищённый ввод выполняется на Mac. Права файловой системы и подтверждения задаёт Desktop; бот их не расширяет. Процент прогресса появляется только при наличии явного файла статуса текущего чата.

## Прямой native-запуск без Docker

Этот раздел сохраняет отдельный запуск Mac без контейнера. Основной Docker-порядок для обеих систем: [Windows и macOS — что скачать и куда вставить](docs/QUICK_START.md).

Следуйте [пошаговой установке](docs/INSTALL_MACOS.md). Потребуются официальный Desktop с выполненным входом, Python 3.11+, собственный новый бот, ваш числовой Telegram ID и HTTPS-адрес панели. Настройка не требует изменения исходного кода.

После подготовки бота и HTTPS из инструкции:

```sh
bash scripts/install-macos-desktop.command
```

Дождитесь окончания задач в Desktop и закройте приложение через **Quit / Cmd+Q**. Затем из папки пакета:

```sh
.venv/bin/codex-telegram-desktop launch
.venv/bin/codex-telegram-desktop doctor
.venv/bin/codex-telegram-desktop run
```

`launch` сообщает только о запуске. `doctor` проверяет установленную сборку и соединение с её движком, без задания модели. `run` запускает Telegram-мост в текущем терминале. Mac, Desktop, мост и HTTPS-туннель должны оставаться включёнными.

На Samsung откройте своего бота → `/chats` → `/use номер` → `/panel`. Выберите ранее существовавший чат. Обычный текст продолжает его. Новый чат создавайте в Desktop. Первое задание модели отправляйте только при готовности к реальному тесту: оно расходует лимиты аккаунта.

## Ежедневная работа

| Действие | Команда или место |
|---|---|
| Выбрать существующий чат | `/chats`, затем `/use номер` |
| Открыть Mini App | `/panel` или меню **Codex** |
| Посмотреть состояние | `/status` |
| Остановить текущую задачу | `/stop` или кнопка остановки |
| Ответить на вопрос / разрешение | Карточка запроса в панели |
| Отправить документ | Загрузка в Mini App, до 10 MB на файл, до пяти вложений к сообщению |
| Получить подготовленный файл | `/files`, затем `/get имя_файла` из папки `telegram-exports` рабочей области |
| Остановить мост | Ctrl+C в терминале `run`; Desktop продолжает работать |
| Вернуться к обычному запуску Desktop | [Откат и восстановление](docs/MACOS_DESKTOP.md) |

При потере соединения результат отправки может быть неизвестен. Сначала откройте исходный чат в Desktop и проверьте его; повторная отправка вручную может создать дубль.

## Проверка и документация

Локальные проверки на искусственных данных:

```sh
python3 -B scripts/test_offline.py
npm install
npx playwright install chromium
node tests/mobile_smoke.cjs
```

`npm install` и установка браузера скачивают зависимости. Сам smoke-тест подменяет Telegram и сервер приложения. Он не подтверждает соединение с Desktop. Реальная приёмка описана в [MOBILE_ACCEPTANCE](docs/MOBILE_ACCEPTANCE.md), устройство и движок браузера записываются в отчёт отдельно.

Его установка для Windows/Linux — [INSTALL_WINDOWS_LINUX](docs/INSTALL_WINDOWS_LINUX.md), обслуживание — [OPERATIONS](docs/OPERATIONS.md). Не смешивайте конфигурации двух режимов.

Передавайте другим пользователям только исходный пакет. Токен, каталог настроек, рабочие файлы, профиль Desktop и локальные журналы каждый владелец хранит у себя. Прочитайте [SECURITY](SECURITY.md) перед открытием HTTPS-доступа. Это сторонний проект, а не официальный Telegram-клиент OpenAI.
