# Безопасность и конфиденциальность

Пакет рассчитан на **одного владельца** под его собственным аккаунтом ОС. Он не предназначен для публичного многопользовательского сервиса. Каждый получатель создаёт своего бота и настраивает собственный доступ. В Mac-режиме используется уже авторизованный Desktop; отдельный CLI-режим требует собственного входа в изолированный профиль.

Выпуск 0.2 остаётся кандидатом. Анализ кода и искусственные тесты снижают риск, но не дают абсолютной гарантии конфиденциальности или совместимости. Реальные Mac, Samsung и модель в подготовительных проверках не использовались; фактический объём — в [RELEASE](docs/RELEASE.md).

## Кому передаются данные

Сообщения и файлы бота проходят через Telegram. Mini App передаёт данные на ваш HTTPS-адрес; при рекомендуемом туннеле TLS завершается у выбранного оператора, который становится отдельной стороной обработки. Это не сквозное шифрование между телефоном и Mac.

Мост обращается к Telegram API для функций вашего бота, а панель загружает официальный Telegram WebApp SDK. Движок Codex самостоятельно обращается к OpenAI и доступным ему сервисам согласно вашей авторизации, политике и заданию. Поэтому весь комплект нельзя считать работающим без внешней сети или передающим данные только Telegram. Установка Python/npm-зависимостей и туннеля также имеет отдельные сетевые обращения.

Выбирайте инфраструктуру, допустимую для ваших данных и правил организации. Публичный URL не заменяет авторизацию. Статическая оболочка панели доступна по URL; защищённые данные API требуют проверки Telegram.

## Локальная граница доверия

В доверенную среду входят пользователь ОС, его процессы, системное хранилище секретов и установленный Desktop/CLI. Пакет не изолирует вас от администратора, вредоносного процесса с тем же UID, компрометации Telegram-аккаунта или собственного небезопасного задания.

Права `0700/0600`, проверка UID клиента и секрет локального сокета ограничивают доступ других пользователей. Они не создают защиту от процесса того же пользователя, который может читать его файлы. Секрет сокета хранится локально и не предназначен для передачи телефону или туннелю.

Выбранная рабочая папка ограничивает доступные через мост чаты и файловые маршруты. Она не является самостоятельной песочницей для всех инструментов модели. Реальную изоляцию исполнения задаёт политика Codex.

## Общие меры бота и Mini App

| Участок | Контроль и ограничение |
|---|---|
| Владелец | Положительный числовой Telegram ID и личный чат; username не предоставляет доступ |
| Mini App | HMAC-проверка `initData`, owner ID, срок 10 минут, отказ при повторяющихся полях |
| HTTP | Loopback-listener; авторизация API, проверка Host/Origin, ограниченный список действий, лимиты тела/частоты/соединений |
| Секрет бота | Разрешённый системный keyring либо явно заданное окружение; скрытого plaintext fallback нет |
| Разрешение | Точные чат, ход и запрос; разовое подтверждение требует контекста для просмотра |
| Сбой | Журнал до изменяющей отправки; неизвестный исход остаётся неизвестным, без автоматического повтора |
| Файлы | До 10 000 000 байт; проверенные имена и пути; выдача только из `telegram-exports`, без произвольного пути |
| Интерфейс | `textContent` для недоверенного текста, Content Security Policy; содержимое запросов не пишется в HTTP access-log |
| Прогресс | Явный статус выбранного чата; прошлое завершение не подставляется в новую фазу |

Помеченные или распознанные как секретные вопросы не предлагаются для ответа через Telegram. Это не универсальный фильтр секретов внутри любого текста: владелец должен учитывать содержимое своих сообщений, документов и результатов.

## Mac Desktop: особые условия

Адаптер подключается к существующему профилю и движку Desktop. Он не копирует авторизацию, не импортирует историю аккаунта в репозиторий и не создаёт отдельный профиль модели. Для подключения приложение штатно перезапускается с обёрткой в окружении только этого процесса.

Перед запуском проверяются официальная подпись, bundle identity, структура исполняемых файлов, сохранённая версия и хеш движка. Приложение не переподписывается, его файлы не заменяются; глобальное окружение и настройки защиты macOS не меняются. При изменении идентичности или хеша подключение прекращается до повторной проверки.

Доступ к встроенному движку проходит через закрытый Unix-сокет: текущий UID, права файлов, секрет и поколение соединения. Наружу публикуется ограниченный API панели, **не сырой сокет или app-server RPC**. При нескольких неоднозначных движках удалённые действия блокируются, без принудительного завершения чужих процессов.

Мост управляет существующими локальными чатами выбранной папки. Sandbox и разрешения наследуются от Desktop; адаптер не гарантирует `read-only`, если сам Desktop настроен иначе. Возможность управлять чатом с телефона означает возможность инициировать действия в рамках этих реальных прав. Настройте их в Desktop до подключения бота.

Ответы с GUI и телефона привязаны к исходному запросу. Первый ответ резервирует его; состояние завершения подтверждает движок. Неизвестные запросы остаются доступными оригинальному клиенту. Рабочая совместимость этого взаимодействия требует аппаратной приёмки.

`CODEX_CLI_PATH` и схема запуска относятся к внутреннему контракту Desktop. Наличие похожей ветки кода в другой ОС и действительная подпись приложения не доказывают совместимость конкретного Mac-выпуска. Обновление может нарушить интеграцию. [Архитектура и откат](docs/MACOS_DESKTOP.md).

## Отдельное CLI-ядро и Windows-адаптер

CLI-ядро создаёт собственный app-server и отдельный `CODEX_HOME`. Оно использует только зарегистрированные им чаты. Начальные настройки — `read-only` и `on-request`; явный `workspace-write` разрешает запись в рабочую область. Эти значения не описывают права Mac Desktop-режима.

Перед созданием дочерних процессов из окружения убираются секрет бота, унаследованные API-ключи и внутренний контекст Desktop. Это не отключает авторизацию, которую сам Codex получает из своего законно настроенного профиля.

Windows-адаптер подключается отдельно и имеет собственные требования Python, IPC и launcher. Прочитайте [его README](adapters/windows_desktop/README.md). Успешные тесты CLI-ядра или Mac-обёртки не подтверждают его живую совместимость.

## Частные данные вне репозитория

`config.json` содержит owner ID, рабочую папку, публичный URL и, в Mac-режиме, сведения об установленном приложении. `state.json` содержит ID и названия чатов, выбор, offset и квитанции. Даже без токена это частные данные.

Mac-адаптер дополнительно хранит данные локальной сессии, секрет сокета, журнал операций и launcher в своей папке настроек. Не копируйте `native-session.json`, `native-operations.json` и соседние файлы в issue или общий архив. Точный состав может меняться между версиями; исключайте всю пользовательскую папку настроек.

Историю и авторизацию Desktop хранит в прежнем профиле. Отдельный CLI хранит свои данные внутри каталога этого режима. Мост держит отображаемые сообщения в памяти, но названия и метаданные могут сохраняться в состоянии. Вложения остаются в рабочей области; приложение не шифрует их отдельно.

Для большого штатного сообщения движка Mac-обёртка использует анонимный временный файл с закрытыми Unix-правами, чтобы сохранить байты и определить получателя без неограниченного разбора JSON в памяти. Он временно содержит исходный payload и закрывается после обработки; это не журнал для публикации и не гарантия физического стирания данных с носителя. Ответ на запрос broker больше 8 MiB отклоняется явно, а штатный кадр Desktop передаётся исходному клиенту. Ограничение может затронуть чтение очень длинной истории.

На Unix настройки записываются с `0600`, каталог — `0700`; на Windows действуют также ACL профиля. Проверьте права переопределённого каталога и политику резервного копирования. Не помещайте его в публичную или общую синхронизируемую папку. Системное шифрование диска не отменяет необходимость ограничивать доступ в активной сессии.

## Отзыв доступа и сообщение о проблеме

При раскрытии токена отзовите его в BotFather, остановите мост и туннель. Для Mac выполните `codex-telegram-desktop set-token`; для CLI — `codex-telegram set-token`. После скрытого ввода нового токена проверьте свой режим и перезапустите мост. Если токен подаётся окружением, обновите его источник: окружение имеет приоритет над keyring.

В CLI есть `forget-token`. У Desktop-режима удаление сохранённой записи выполняется средствами Keychain для account, соответствующего именно его каталогу; не удаляйте записи других установок. Прекратить подключение Mac-адаптера можно штатным выходом из Desktop и обычным запуском либо командой `rollback`. Остановка моста не останавливает уже идущие задачи Desktop.

Для другого владельца используйте отдельные бот и каталог. Не передавайте ему копию профиля, конфигурации или хранилища секретов. Если секрет попал в Git, простого удаления файла недостаточно: сначала отзовите его, затем очистите историю.

Для сообщения об уязвимости включите в своём GitHub-репозитории private vulnerability reporting. Передавайте минимальный искусственный пример, режим, версии и код ошибки. Не публикуйте токены, `initData`, ID реальных чатов, личные пути, переписку или файлы сокета.

## Основания и проверки

Валидация Mini App основана на [официальном протоколе Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app), хранение токена — на [keyring](https://pypi.org/project/keyring/), сообщения движка — на [Codex app-server](https://learn.chatgpt.com/docs/app-server). Эти источники не предоставляют официальной гарантии поддержки данного Desktop-адаптера.

Публичный архив проверяется по разрешённому списку файлов, содержимому и контрольным суммам. Ноль совпадений одного сканера не доказывает полное обезличивание. Реальные Mac/Samsung, сетевой бот, модель и восстановление после сна должны пройти [отдельную приёмку](docs/MOBILE_ACCEPTANCE.md); невыполненные проверки отмечаются `NOT_RUN`, а не успехом.
